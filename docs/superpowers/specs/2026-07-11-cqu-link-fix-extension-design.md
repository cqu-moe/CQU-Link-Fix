# CQU Link Fix 浏览器扩展设计

日期：2026-07-11

状态：已确认，待实施计划

## 1. 摘要

CQU Link Fix 是一个面向 Chromium 浏览器、基于 Manifest V3 的重庆大学链接修正扩展。首版解决两类问题：

1. 将指定的重庆大学站点导航改写为重庆大学 aTrust Web 代理地址，减少校外访问和统一身份认证中的额外操作。
2. 将重庆大学团委网站的内网文章路径改写为公网可访问的参数式链接。

首版采用混合重定向架构：可靠性敏感的精确规则由 `declarativeNetRequest` 在请求发出前执行；用户主动开启的“全部 CQU 域名”模式由后台 service worker 计算任意域名的 aTrust 地址。

首版 UI 是功能性雏形。它必须清楚解释当前改写、允许一次性绕过和管理规则，但不追求最终视觉质量。视觉重设计属于后续工作。

## 2. 目标

- 默认将 `sso.cqu.edu.cn` 的主框架导航改写到 aTrust 代理，保持 CAS 客户端通信正确。
- 支持随扩展版本发布的“重要站点”域名名单。
- 支持随扩展版本发布的完整 IP + 端口名单。
- 提供默认关闭的“全部 `*.cqu.edu.cn`”改写开关。
- 修正团委文章链接：

  ```text
  https://youth.cqu.edu.cn/info/{wbtreeid}/{wbnewsid}.htm
  →
  https://youth.cqu.edu.cn/content.jsp?urltype=news.NewsContentUrl&wbtreeid={wbtreeid}&wbnewsid={wbnewsid}
  ```

- 支持用户在本地停用内置规则、添加精确规则和排除规则。
- 所有改写均可解释、可停用、可单次绕过。
- 无远程规则服务、无遥测、无浏览历史或请求体采集。

## 3. 非目标

- 首版不支持 Firefox。
- 首版不修改 `auth.cqu.moe` 服务端的 CAS 自动化流程。该流程运行在远端节点中的独立浏览器，用户安装的扩展无法影响它。
- 首版不提供远程规则热更新；内置规则随扩展版本更新。
- 首版不尝试推断或扫描任意 IP 服务。
- 首版不保证任意未被重庆大学 aTrust 发布的地址可以通过公式访问。
- 首版不提供最终视觉设计。
- 首版不读取或修改登录表单、密码、验证码、Cookie、localStorage 或请求体。

## 4. 已确认事实与设计假设

### 4.1 域名型 aTrust 地址

已观察并公开可访问的映射：

```text
https://sso.cqu.edu.cn/login
→
https://sso-cqu-edu-cn-s.atrust.cqu.edu.cn/login
```

域名型转换规则为：

```text
http(s)://{hostname}{path}{query}{fragment}
→
https://{hostname 中的点替换为连字符}-s.atrust.cqu.edu.cn{path}{query}{fragment}
```

输出协议固定为 HTTPS。扩展不依赖 `-s` 的自然语言含义，只把它视为重庆大学当前 aTrust 域名代理格式的一部分。

### 4.2 IP + 端口型 aTrust 地址

已观察的格式为：

```text
http(s)://1.1.1.1:8000/path
→
https://1-1-1-1-8000-p.atrust.cqu.edu.cn/path
```

扩展不依赖 `-p` 的自然语言含义。首版只处理规则注册表中明确列出的完整 IP + 端口组合，不允许将任意 IP 自动套用公式。

IP 规则只有在真实、已授权资源完成校外烟测后才能进入默认启用的内置名单；未经验证的规则不得发布为默认规则。

### 4.3 aTrust 发布边界

aTrust Web 代理地址是否有效取决于学校侧是否发布了对应资源。公式正确不代表目标一定存在。因此，精确内置名单是首版的安全默认；全域模式由用户主动开启并承担未发布站点失败的可能性。

## 5. CAS 正确性不变量

CAS 是本扩展风险最高的链路。首版必须满足以下不变量：

1. 只改写当前浏览器导航 URL 的外层 SSO 主机。
2. `service` 查询参数的解码值在转换前后必须完全相同。
3. 不把 `service` 内的客户端回调地址转换成 aTrust 地址。
4. 不二次编码 `service`、`redirect_uri`、`state` 或其他嵌套 URL 参数。
5. CAS 签发的 `ST-*` 必须继续返回原始客户端回调。
6. 扩展不读取、存储或转发票据内容。

示例：

```text
输入导航：
https://sso.cqu.edu.cn/login?service=https%3A%2F%2Fmy.cqu.edu.cn%2Fauthserver%2Fauthentication%2Fcas

改写后：
https://sso-cqu-edu-cn-s.atrust.cqu.edu.cn/login?service=https%3A%2F%2Fmy.cqu.edu.cn%2Fauthserver%2Fauthentication%2Fcas

成功回调：
https://my.cqu.edu.cn/authserver/authentication/cas?ticket=ST-...
```

“改写后能显示登录页”不是完整验收。发布前必须证明真实客户端收到 ST 后能建立业务会话。

## 6. 总体架构

### 6.1 组件

#### Rule Core

不依赖 Chrome API 的纯函数模块，负责：

- URL 解析与规范化。
- 域名型 aTrust 转换。
- IP + 端口型 aTrust 转换。
- 团委文章路径转换。
- CAS 嵌套参数不变量检查。
- 循环检测与目标合法性校验。

#### Rule Registry

合并三类规则来源：

- 随扩展发布的内置规则。
- `chrome.storage.local` 中的用户精确规则。
- 用户排除项和功能开关。

内置规则包含稳定 ID、说明、类别、默认状态、匹配条件、转换器和验证状态。内置规则升级时以稳定 ID 合并用户的启用/停用选择。

#### DNR Compiler

将以下规则编译为 `declarativeNetRequest` 静态、动态或会话规则：

- 统一身份认证核心规则。
- 重要域名名单。
- 已验证 IP + 端口名单。
- 团委链接修正。
- 用户精确重定向。
- 用户排除与一次性绕过。

#### Navigation Fallback

后台 service worker 只负责无法用固定 DNR 规则表达的“全部 CQU 域名”算法转换。它只处理主框架导航，并在执行前调用 Rule Core。

#### Popup

面向当前标签页，显示：

- 扩展是否运行。
- 当前 URL 是否被改写、由哪条规则改写。
- 原始主机与目标主机。
- “原地址打开一次”。
- “暂停当前站点”。
- “管理全部规则”。

#### Options Page

面向长期配置，提供：

- 核心认证、重要站点、IP 名单、附加修正的分组管理。
- 全域模式开关和权限申请说明。
- 本地自定义精确规则。
- 排除名单。
- 规则来源、默认状态和匹配范围说明。

### 6.2 数据流

```text
主框架导航
  → DNR 高优先级排除/绕过
  → DNR 用户精确规则
  → DNR 团委/核心/名单规则
  → service worker 全域模式兜底
  → Rule Core 生成并校验目标
  → 浏览器导航到目标
```

扩展只处理 `main_frame`。首版不重写 XHR、fetch、WebSocket、iframe 或其他子资源。

## 7. 规则模型与优先级

规则按以下顺序求值：

1. 循环保护：目标已属于 `*.atrust.cqu.edu.cn` 时终止。
2. 当前标签页的一次性绕过和用户排除规则。
3. 用户精确覆盖规则。
4. 团委等附加路径修正。
5. 核心认证、重要域名和 IP + 端口名单。
6. 默认关闭的全 CQU 域名模式。

首个终止型规则获胜。附加路径修正可以产生一次新的导航；如果用户开启全域模式，新导航仍可继续被 aTrust 规则处理。这是显式全域模式的预期行为。

### 7.1 默认状态

| 类别 | 默认状态 | 用户控制 |
| --- | --- | --- |
| 总开关 | 开启 | 可关闭 |
| 统一身份认证 | 开启 | 可停用、可单次绕过 |
| 已知重要站点 | 开启 | 每条可停用 |
| 已验证 IP + 端口 | 按规则配置 | 每条可停用 |
| 团委公网链接 | 开启 | 可停用 |
| 全部 `*.cqu.edu.cn` | 关闭 | 需主动授权后开启 |
| 用户自定义规则 | 无 | 用户本地管理 |

### 7.2 循环保护

- 不处理任何已经以 `.atrust.cqu.edu.cn` 结尾的主机。
- 对每次导航记录原始 URL、目标 URL 和命中规则 ID，仅保留在内存或会话存储中。
- 同一标签页中同一转换对重复出现时停止并提示。
- 不通过添加永久查询参数标记改写状态，避免污染 CAS `service` 和业务 URL。

## 8. 权限模型

首版遵循最小权限原则：

- `storage`：保存本地设置和规则。
- `declarativeNetRequestWithHostAccess`：执行请求前重定向。
- `webNavigation`：处理全域模式和导航结果状态。
- 必要的标签页导航能力：执行一次性绕过和显示当前页面状态。
- 精确 `host_permissions`：仅覆盖默认内置规则需要的来源和目标。
- 可选 `*.cqu.edu.cn` 主机权限：仅在用户开启全域模式时请求。

实现阶段必须用真实 Chromium 验证动态精确 IP 规则的按需权限流程。如果 Chromium 无法在不声明宽泛可选权限的情况下授予单个自定义 IP origin，首版自定义 IP 功能应限制为内置名单，不得为了便利默认申请 `<all_urls>`。

用户拒绝全域权限时，开关保持关闭，核心精确规则继续工作。

## 9. 状态与本地数据

所有配置存入 `chrome.storage.local`：

- 总开关和分类开关。
- 内置规则的用户覆盖状态。
- 用户自定义精确规则。
- 排除规则。
- 最近一次可解释的改写元数据。

不使用自建后端，不上传设置，不同步私人 IP 名单。内置规则是扩展包的一部分。

一次性绕过使用会话级状态或 DNR session rule，只对当前标签页、当前原始 URL 生效一次；导航完成或标签页关闭后立即清除。

## 10. 错误处理与回退

### 10.1 无效规则

- 非 HTTP(S) URL、userinfo、无效端口、非法主机和会产生循环的目标在保存前拒绝。
- DNR 不支持的正则在启用前验证并给出本地错误。
- 内置规则编译失败时不加载该规则，并在设置页标记错误，不阻断其他规则。

### 10.2 aTrust 页面失败

- 扩展不自动静默回退到原始地址。
- 能检测到导航错误时，图标显示警告。
- 用户可从弹窗选择“原地址打开一次”。
- aTrust 返回 HTTP 200 错误页时可能无法被可靠识别；因此弹窗始终提供手动绕过，而不依赖自动检测。

不自动降级可以避免在用户不知情时改变认证路径，也避免 CAS 在连续自动跳转中循环。

### 10.3 全域模式中的未发布站点

未发布站点可能失败。失败不会自动加入内置名单或自动改写为其他地址。用户可以暂停当前站点或添加排除规则。

## 11. UI 功能范围

首版 UI 的验收标准是可理解和可操作：

- 用户能看出扩展是否启用。
- 用户能看出当前页面由哪条规则改写。
- 用户能看到原始主机和目标主机。
- 用户能一次性打开原地址。
- 用户能停用当前站点或管理所有规则。
- 请求宽泛权限前有明确说明。

首版不以配色、动效、品牌视觉或精细响应式布局作为发布阻塞项。功能稳定后单独进行 UI/UX 设计。

## 12. 测试策略

### 12.1 Rule Core 单元测试

- 域名中的点正确转换为连字符。
- 输出协议始终为 HTTPS。
- path、query 和 fragment 按规则保留。
- CAS `service` 解码值严格不变。
- 已经是 aTrust 的目标不会再次转换。
- IP 仅在完整 host + port 命中名单时转换。
- 团委 `wbtreeid` 和 `wbnewsid` 正确提取。
- 非法 URL、IPv6、userinfo、缺失端口和不支持协议按明确策略拒绝。

### 12.2 DNR 编译测试

- 内置规则 ID 稳定且不冲突。
- 动态排除规则优先于内置重定向。
- 一次性绕过规则只匹配预期 URL。
- 规则更新是原子的，不留下旧规则。
- 正则在 Chromium 的支持检查中通过。

### 12.3 扩展集成测试

- 地址栏、链接点击、CAS 302 和新标签页均能触发预期规则。
- 刷新、前进、后退不会循环。
- 开关变化立即更新规则。
- 拒绝全域权限后核心规则仍工作。
- 升级内置规则后保留用户的停用选择。

### 12.4 真实网络烟测

发布前必须覆盖：

| 网络 | aTrust 客户端 | 场景 |
| --- | --- | --- |
| 校园网 | 未连接 | 域名 aTrust 地址、CAS 登录和回调 |
| 非校园网 | 未连接 | 域名 aTrust 地址、CAS 登录和回调 |
| 非校园网 | 已连接 | 不冲突、不循环 |
| 校园网或非校园网 | 未连接 | 每一条拟发布的 IP + 端口规则 |

至少选择一个真实 CAS 客户端完成端到端验证，例如 `my.cqu.edu.cn`：

1. 客户端跳转到原始 SSO 登录 URL。
2. 扩展只改写外层 SSO 主机。
3. 登录成功后返回原始客户端 callback。
4. 客户端消费 ST 并建立有效业务会话。
5. 回调 URL、票据参数和后续页面没有被再次错误改写。

## 13. 发布验收条件

- 所有 Rule Core、DNR 编译和扩展集成测试通过。
- `service` 不变量测试覆盖编码、已有查询参数和特殊字符。
- 校园网与非校园网真实 CAS 烟测通过。
- 证明非校园网且未连接 aTrust 客户端时的实际行为；若不能访问，UI 和文档必须准确说明前置条件。
- 每个默认启用的 IP + 端口规则都有真实授权资源的验证记录。
- 团委示例文章从 `/info/...htm` 稳定转到对应 `content.jsp` 页面。
- 拒绝宽泛权限不会破坏核心精确规则。
- 未发现重定向循环、票据丢失或嵌套 URL 二次编码。
- 扩展没有远程规则请求、遥测、历史读取或请求体读取。

## 14. 后续工作

- 独立设计 `auth.cqu.moe` 服务端通过 aTrust 获取 CAS 会话和 ST 的方案。
- 完成首版后重新设计 popup、options page 和品牌视觉。
- 根据实际使用补充已验证域名和 IP + 端口名单。

- Chromium 版本稳定后评估 Firefox 适配。

## 15. 实施前验证门

以下事项不是未定义需求，而是实施和发布过程中的强制验证门：

1. 在非校园网、未连接 aTrust 客户端的环境复测域名型代理地址。
2. 用一个真实、已授权的 IP + 端口资源验证 `-p` 格式。
3. 用真实 CAS 客户端完成登录与 callback 验证。
4. 验证 Chromium 对自定义精确 IP origin 的最小权限授予能力；不满足时禁用首版自定义 IP，只保留内置名单。

扩展实现不得绕过这些验证门，也不得把未验证推断作为默认启用规则发布。
