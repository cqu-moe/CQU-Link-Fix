# 内置规则连续列表设计

## 目标

将设置页的内置规则呈现为一个连续列表，删除“重要站点 / IP 名单 / 附加修正”等次级标题与空分组占位。现有规则和后续新增的域名、IP、链接修正规则都使用同一种规则行顺序追加。

## 信息结构

当前列表只有两项，顺序沿用内置规则定义：

1. 统一身份认证
2. 团委官网链接

不添加“教务网”、IP 占位或其他尚未实现的规则。规则类别仍可保留在内部数据中用于匹配与维护，但不再影响设置页的视觉分组。

## 视觉与交互

- `内置规则` 面板内直接渲染规则行，不出现 `fieldset`、组标题、组说明或组空态。
- 第一行不显示顶部分隔线；后续规则行使用完整的 `1px solid var(--border-soft)` 分隔线。
- 每行继续显示规则名、状态、说明、匹配范围和开关。
- 规则行的开关组件、150ms 动效、启停逻辑、验证错误和锁定状态保持不变。
- 列表为空时只显示一个面板级空态“当前版本暂无内置规则。”。

## 数据与兼容性

`buildOptionsModel` 直接按传入的 `builtInRules` 顺序返回 `rules`，并继续通过稳定规则 ID 合并启停状态和验证错误。规则 ID、DNR ID、匹配器、转换器、类别和已有用户设置均不改变。

## 验证

- 模型测试锁定连续规则数组及顺序。
- 控制器测试确认页面不存在次级分组节点、组标题和 IP 空态，同时两条现有规则都直接位于内置规则面板下。
- CSS 合约测试锁定只有相邻规则行之间存在分隔线。
- 完整类型检查、单元测试、生产构建和 Chromium 端到端测试通过后，再重新加载本机扩展进行视觉确认。
